# Internationalization: English + ខ្មែរ

## Rules

1. **No hard-coded UI strings.** Every user-visible string in JSX goes through `t()`. ESLint
   (`i18next/no-literal-string`) fails the build otherwise.
2. **English is the source of truth for keys.** Keys are type-checked against `web/src/locales/en/*.json`
   (`t('missing.key')` is a compile error). `npm run i18n:check` (run in CI) fails when Khmer is missing
   a namespace or key, has an empty value, has different `{{placeholders}}`, or has stale keys.
3. **The API returns codes, not sentences.** Translate `error.code` via `errors:codes.<CODE>`; translate
   validation failures via `errors:rules.<rule>`. A Go test fails if an `apperr` code lacks an EN or KM entry.
4. **Technical content is never translated:** logs, YAML, commands, code, resource names, versions,
   branch names, commit SHAs. Keep them in `font-mono` elements.

## Language selection

`user profile (users.locale)` → `saved choice (localStorage)` → `browser Accept-Language` → `en`.

The same order is applied server-side (`internal/i18n.Negotiate`) for notifications and emails, which
are rendered with Go `text/template` + go-i18n bundles in `internal/i18n/locales/*.json`.

## Adding strings

1. Add the key to `web/src/locales/en/<namespace>.json`.
2. Add the Khmer translation to `web/src/locales/km/<namespace>.json` (same key path, same placeholders).
3. New namespace? Create the file in **both** folders and register its type in `src/i18n/i18next.d.ts`.
   It's bundled automatically.
4. Run `npm run i18n:check`.

## Khmer typography

| Concern | Implementation |
|---|---|
| Fonts | **Noto Sans Khmer** (body), **Kantumruy Pro** (headings), self-hosted via `@fontsource` — no font CDN |
| Stacked consonants (ជើង) / vowel signs | `:lang(km)` body line-height **1.7**, headings 1.5; buttons use `min-h-*` not fixed `h-*`; `truncate-khmer` utility adds vertical padding for single-line truncation |
| No spaces between words | CSS `overflow-wrap: anywhere` as a safety net; `insertWordBreaks()` (`src/i18n/segment.ts`) inserts U+200B at `Intl.Segmenter('km', {granularity:'word'})` boundaries for narrow cells, badges, toasts |
| Regression tests | Playwright `e2e/i18n.spec.ts` asserts no element that clips overflow contains overflowing Khmer text, fonts load, and nothing overflows horizontally at 360px |

## Dates, numbers, time zones

- Use `useFormat()` (`dateTime`, `number`, `relative`, `duration`) — never `toLocaleString()` directly.
- Storage and API are UTC; display timezone defaults to **Asia/Phnom_Penh** and is user-configurable.
- **Khmer numerals (០១២៣…)** are an opt-in preference for the Khmer UI. They are produced by
  transliteration (`toKhmerDigits`) rather than `-u-nu-khmr`, so they work even in engines that lack
  Khmer locale data (some embedded Chromium/webviews). On such engines, month/day names fall back to English.

## Notifications & email

Telegram, Slack, Email and Webhook messages are rendered **per recipient** in their `users.locale`
(channel-level `locale` overrides it for shared channels, e.g. a team Telegram group). Templates are Go
`text/template` / `html/template` files under `internal/notify/templates/{en,km}/`; strings come from
go-i18n bundles in `internal/i18n/locales/`. A Go test fails on missing KM messages or templates. Email
HTML declares `lang` and a Khmer-capable font stack. Webhook payloads stay machine-readable (codes +
data), plus an optional `text` field in the channel locale.

## Verifying Khmer layout (Definition of Done)

For every new page, Playwright runs the page in `km` at 360 px, 768 px and 1280 px and:
asserts no clipped Khmer text and no horizontal overflow (see `e2e/i18n.spec.ts`), and saves screenshots
to the CI artifacts for visual review. Tables, badges, buttons and toasts use `min-h-*`, never fixed
heights.
